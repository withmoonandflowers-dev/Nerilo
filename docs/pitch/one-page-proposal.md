# Nerilo：中央掛掉也能通的加密通訊（一頁提案）

## 問題

台灣的日常通訊幾乎全押在集中式服務上。地震、颱風、海纜受損、基地台過載，任何一環出事，
LINE 和 Messenger 就是一起斷。對防災單位、偏鄉社區、需要隱私保障的族群（記者、社工、
受暴者支援網絡）來說，「平時方便」的代價是「關鍵時刻不可用，且平台看得到一切」。

## 方案

Nerilo 是一套瀏覽器就能跑的點對點加密通訊技術。三個核心能力：

1. **不經伺服器的加密通訊**：訊息走裝置對裝置的 WebRTC 直連，內容以端到端加密保護，
   伺服器只在「第一次牽線」時參與，之後的成員由既有成員互相介紹，連牽線都不經伺服器
   （已實測：第三人加入時零伺服器寫入）。內容全程加密，伺服器看不到明文。
2. **收件者離線也送得到（盲信使）**：對方不在線時，訊息以密文寄放在路過的陌生節點上，
   回線後自動領取。信使全程只見密文，驗得了真偽、讀不了內容，送達後憑雙方共簽的收據
   賺取點數，形成互助循環。
3. **別人可以直接拿去用（SDK）**：整套能力封裝成可嵌入的開源 SDK，其他公益專案（社區
   防災 App、匿名通報系統）不需要理解密碼學細節，帶自己的後端即可串接。

## 為什麼可信（可查核的技術主張）

- 訊息「恰好一次」送達：寄收兩端不掉訊、不重複，有自動化端對端測試持續驗證。
- 端到端加密：伺服器與信使僅見密文，經第三方視角的核心不變量稽核（報告隨附，
  結論為有條件通過，已知風險全數自我揭露並排入處置）。
- 品質制度：1,544 項單元測試、模擬多人情境的自動化瀏覽器測試、CI 硬性閘門，
  每次改動都須通過才能合併。
- 全部開源，稽核報告與架構決策紀錄（36 篇 ADR）公開可驗。

## 社會影響

- **防災韌性**：中央服務中斷或平台不可用時，已成形的社區網路仍能靠裝置互相中繼與代存
  繼續通訊，不需要任何一台伺服器活著。
- **隱私人權**：通訊內容不落任何第三方之手，適合高風險溝通場景。
- **公共財**：以 SDK 形式開放，讓影響力不限於單一 App，而是一層可被重複使用的基礎能力。

## 現況與需求

現況：可操作的網頁版 demo（三分鐘可演示離線代存送達全流程）、已發佈於 npm 的 SDK、完整稽核文件。

**誠實邊界（請一併評估）**：目前「兩個素未謀面的裝置第一次連線」仍需要一個雙方都到得了的
會合點，這是 WebRTC 的固有限制，不是實作缺陷。因此在網路全斷的情境下，尚未連過的成員無法
建立新連線；已連上的網路則不受影響。要補上這一段，需要本地會合（區域網內自架會合點）
與異質傳輸橋接（LoRa）兩項研究，正是本申請的標的。

本專案為個人與 AI 協作開發，申請資源將用於：本地會合與 LoRa 橋接的先期研究、TURN 中繼與
測試基礎設施費用、多裝置實地測試（偏鄉或演習場景）、SDK 文件與範例的在地化整理。
