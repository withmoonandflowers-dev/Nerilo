# 上板與部署手冊

> 本檔保留舊連結相容性。完整、最新且唯一的部署事實來源是
> [DEPLOYMENT.md](DEPLOYMENT.md)；不要從歷史 commit 複製 token-based CI 或
> 未指定 `--only` 的 Firebase 指令。

## 現行部署邊界

| 元件 | 現行方式 |
|---|---|
| React production | `master` 通過硬閘後，由 `firebase-deploy.yml` 自動部署 Hosting + Firestore rules/indexes |
| React staging | `npm run deploy:staging:safe`，發布到 `nerilo-staging` preview channel |
| Nuxt/Vue candidate | 手動執行 `web-vue-preview.yml` 或 `npm run deploy:web-vue:preview`；只能進 `nerilo-staging` |
| Firebase Functions | CI 只建置、不部署；Blaze／runtime／secrets 決策未完成 |
| Netlify webhook | 由 `netlify.toml` 與 Netlify Git integration 獨立部署 |
| MCP | 本機 stdio process，沒有遠端部署 |

## 常用指令

```bash
# React staging
npm run deploy:staging:safe

# React production Hosting（不含 Functions）
npm run deploy:production:safe

# Nuxt/Vue candidate preview
cp web-vue/.env.preview.example web-vue/.env.preview
npm run deploy:web-vue:preview
```

以上 web deploy 都會在建置前檢查六個 Firebase 設定與 project ID。

## Functions 防誤部署

直接執行 `npm run deploy:full` 會在建置前被阻擋。只有在完成 Functions
runtime、Twilio config、secrets、region、Cloud Build API 與 Blaze 預算審查後，
才可明確覆寫：

```bash
npm run deploy:full -- --confirm-functions-and-billing
```

PowerShell 同樣需要雙重意圖：

```powershell
.\scripts\deploy.ps1 -Full -ConfirmFunctionsAndBilling
```

## CI 認證

Production workflow 使用 `FIREBASE_SERVICE_ACCOUNT_NERILO`，不是舊式
`FIREBASE_TOKEN`。Vue preview 使用 staging 專用
`FIREBASE_SERVICE_ACCOUNT_NERILO_STAGING`，且 workflow 會驗證 JSON 內的
`project_id` 必須是 `nerilo-staging`。

Node、Java、GitHub secrets、preview 建立與 rollback 步驟請直接查閱
[DEPLOYMENT.md](DEPLOYMENT.md)。
